v0.91 (Build 87)
──────────────────────
BUG FIX — Cancel doesn't kill ffmpeg / ffmpeg survives app quit

Root cause: proc.kill() on Windows only terminates the exact PID it targets.
When yt-dlp spawns ffmpeg as a child process, killing yt-dlp leaves ffmpeg
running as an orphan — still encoding, still holding temp files open.
The same issue affected app quit: by the time the Electron before-quit
taskkill fired, Flask had already exited (via /api/shutdown), and the
orphaned yt-dlp+ffmpeg processes were no longer in Flask's process tree.

Fixes:
  - New _kill_proc() helper: on Windows uses taskkill /F /T /PID which
    kills the entire process tree (yt-dlp + ffmpeg children). On other
    platforms falls back to proc.kill().
  - New _active_procs registry: maps job_id → proc, maintained with a
    threading.Lock. Populated on proc start, cleared on proc exit or
    exception — never leaks.
  - cancel_download: now calls _kill_proc() instead of proc.kill()
  - /api/shutdown: now kills all active procs via _kill_proc() BEFORE
    calling os._exit(0), so no orphans survive the app quit

Applies to both audio and video downloads uniformly.
File cleanup (_cleanup) was already correct — it now fires reliably
because proc.wait() returns promptly once the full tree is dead.

v0.91 (Build 86)
──────────────────────
BUG FIX — Cards not minimizing after Download All Audio/Video

Root cause: stale DOM references in the bulk download poller.
When playlist items finish loading their full info in the background,
fetchPlaylistEntries calls renderCard() a second time using innerHTML —
this destroys and recreates the card's DOM elements (stEl, dlBtn, progEl).
The wiv setInterval poller had captured these elements at the start of
downloadOne, so it was holding detached (no-longer-in-document) nodes.
When status='done', stEl.closest('.vcard') on a detached node returns null,
minimizeDoneCard fell into the no-card branch, and the card stayed as-is.

Fix: wiv poller now re-fetches stEl, dlBtn, and progEl via getElementById
on every tick before calling applyJobProgress and applyJobDone.
Falls back to the originally captured reference if the element is gone
(e.g. item removed mid-download).

- Auto-close on update: app quits after NSIS installer launches
- Footer: 'Check for Updates 🔄' moved after version number

v0.91 (Build 85)
──────────────────────
CRITICAL BUG FIX — Download All Audio deadlock

Root cause: classic subprocess pipe buffer deadlock.
When running yt-dlp with -x (audio extraction), ffmpeg writes
codec info and per-frame progress to stderr during MP3 encoding
— easily 100KB+ for a 3-minute track. The OS pipe buffer fills
(~64KB), ffmpeg blocks waiting for it to drain, yt-dlp blocks
waiting for ffmpeg, and our stdout reading loop waits forever.

Fix: stderr is now drained in a background daemon thread while
the stdout loop runs. The process can always write to stderr
without blocking, regardless of how much it outputs.

Also fixed:
  - Auto-update: app now quits automatically after NSIS installer
    launches (after 1.5s delay), so installer can replace files cleanly
  - Footer: "Check for Updates 🔄" moved to after the version number

v0.91 (Build 87)
──────────────────────
BUG FIX — Cancel doesn't kill ffmpeg / ffmpeg survives app quit

Root cause: proc.kill() on Windows only terminates the exact PID it targets.
When yt-dlp spawns ffmpeg as a child process, killing yt-dlp leaves ffmpeg
running as an orphan — still encoding, still holding temp files open.
The same issue affected app quit: by the time the Electron before-quit
taskkill fired, Flask had already exited (via /api/shutdown), and the
orphaned yt-dlp+ffmpeg processes were no longer in Flask's process tree.

Fixes:
  - New _kill_proc() helper: on Windows uses taskkill /F /T /PID which
    kills the entire process tree (yt-dlp + ffmpeg children). On other
    platforms falls back to proc.kill().
  - New _active_procs registry: maps job_id → proc, maintained with a
    threading.Lock. Populated on proc start, cleared on proc exit or
    exception — never leaks.
  - cancel_download: now calls _kill_proc() instead of proc.kill()
  - /api/shutdown: now kills all active procs via _kill_proc() BEFORE
    calling os._exit(0), so no orphans survive the app quit

Applies to both audio and video downloads uniformly.
File cleanup (_cleanup) was already correct — it now fires reliably
because proc.wait() returns promptly once the full tree is dead.

v0.91 (Build 86)
──────────────────────
BUG FIX — Cards not minimizing after Download All Audio/Video

Root cause: stale DOM references in the bulk download poller.
When playlist items finish loading their full info in the background,
fetchPlaylistEntries calls renderCard() a second time using innerHTML —
this destroys and recreates the card's DOM elements (stEl, dlBtn, progEl).
The wiv setInterval poller had captured these elements at the start of
downloadOne, so it was holding detached (no-longer-in-document) nodes.
When status='done', stEl.closest('.vcard') on a detached node returns null,
minimizeDoneCard fell into the no-card branch, and the card stayed as-is.

Fix: wiv poller now re-fetches stEl, dlBtn, and progEl via getElementById
on every tick before calling applyJobProgress and applyJobDone.
Falls back to the originally captured reference if the element is gone
(e.g. item removed mid-download).

- Auto-close on update: app quits after NSIS installer launches
- Footer: 'Check for Updates 🔄' moved after version number

v0.91 (Build 85)
──────────────────────
CRITICAL BUG FIX — Download All Audio deadlock

Root cause: classic subprocess pipe buffer deadlock.
When running yt-dlp with -x (audio extraction), ffmpeg writes
codec info and per-frame progress to stderr during MP3 encoding
— easily 100KB+ for a 3-minute track. The OS pipe buffer fills
(~64KB), ffmpeg blocks waiting for it to drain, yt-dlp blocks
waiting for ffmpeg, and our stdout reading loop waits forever.

Fix: stderr is now drained in a background daemon thread while
the stdout loop runs. The process can always write to stderr
without blocking, regardless of how much it outputs.

Also fixed:
  - Auto-update: app now quits automatically after NSIS installer
    launches (after 1.5s delay), so installer can replace files cleanly
  - Footer: "Check for Updates 🔄" moved to after the version number
    (now last in footer), emoji appended after text
